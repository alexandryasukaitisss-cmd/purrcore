# ADR 0001: локальный однопроцессный монитор

## Решение

PurrCore — нативное macOS-приложение на SwiftUI с узким AppKit-мостом для
режима без Dock. Системные метрики читаются напрямую через Mach, `libproc`,
`getifaddrs` и IOKit. История хранится в системной SQLite без отдельного демона,
облачной синхронизации и сторонних runtime-зависимостей.

Каждый Mac является отдельной границей данных и исполнения. Установки на
MacBook Air и Mac mini не обмениваются состоянием, не используют общую базу и
не требуют доступности второго компьютера.

## Сценарии качества

- В фоне приложение обновляет общие метрики раз в секунду и подробные группы
  процессов раз в 5–15 секунд. Цель на Mac mini M4 — менее 0,7% среднего CPU и
  менее 60 MB resident memory при закрытом окне.
- История общих метрик записывается раз в 15 секунд, группы процессов — раз в
  минуту. Данные старше 7 дней удаляются на старте и затем каждый час.
- Бодрствование накапливается только между непрерывными наблюдениями. События
  сна и выключения закрывают интервал; разрыв наблюдения длиннее пяти секунд не
  засчитывается.
- Сессия батареи хранит фактическое бодрствование между отключением и следующим
  подключением питания. Сон внутри сессии не добавляет время.
- Оценка 0–100% — взвешенная экстраполяция фактического бодрствования на один
  процент заряда по двум-трём последним сессиям с известными границами и
  расходом не менее 10%. Неизвестные границы исключают сессию из прогноза.
- График получает не более 720 агрегированных точек независимо от диапазона.
- База хранит только агрегаты и понятные названия групп. Командные строки,
  заголовки окон, документы и содержимое задач не записываются.
- При недоступной базе живые метрики и кошка продолжают работать; ошибка
  истории показывается в интерфейсе.

## Почему без helper daemon

Отдельный агент усложнил бы установку, обновление, наблюдаемость и завершение
процессов, не улучшив текущий недельный локальный сценарий. Его стоит вводить
только если появится подтверждённая потребность собирать данные, когда UI явно
не запущен.

## Почему без shell polling

Запуск `ps`, `top`, `vm_stat` и других процессов каждую секунду создаёт лишнюю
нагрузку и хрупкий текстовый контракт. Нативные API дешевле и возвращают
структурированные значения.

## Мост задач

`purrcorectl` пишет только маркеры `begin`/`end` в ту же базу. MemPalace или
другой исполнитель может оборачивать команду через `purrcorectl run`; обратная
зависимость PurrCore от MemPalace не вводится.
